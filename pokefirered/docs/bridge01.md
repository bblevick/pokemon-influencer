# BRIDGE-01 allocation and PING contract

Scope: debug transport only. ROM → reserved mailbox → mGBA Lua listener → local Python PING responder → mailbox → ROM acknowledgement. No NPC, battle-policy, roster, social, persistent-host or model logic. This is not BRIDGE-02's production transport or save pairing.

## Allocation and feature flags

Supported source: pret `037335f4c725d7c9aecdac87066f2002b4bd7e14`, matching Phase 0 agbcc/toolchain. English FireRed revision 0, MODERN=0 only. `PI_BRIDGE=0` is the default. The isolated enabled test build sets `PI_BRIDGE=1 PI_BRIDGE_TEST=1`; the trigger is absent without the test flag. Use `Makefile.phase1`, never root `make`, which collides with the user's dump filename.

`ld_script.ld` places a separate NOLOAD `pi_mailbox` section at `ORIGIN(EWRAM) + SIZEOF(ewram)`, with alignment and overflow/overlap assertions. `src/pi_bridge.c` explicitly initializes the section-attributed allocation so agbcc does not turn it into COMMON. The initial uninitialized attempt actually landed in IWRAM; the failed manifest/log are retained. Initialization is essential for this compiler.

The successful ELF resolves `gPiMailbox` to **0x0203FBB0**, size **108**, end **0x0203FC1C**. These values are generated, never separately maintained in Lua/Python. All 947 original RAM symbol records (including duplicate static names) retain address/size. The first checker collapsed duplicate static names; it was corrected to compare full symbol records. The original EWRAM section remains 0x3FBB0 bytes, leaving 996 bytes after the mailbox. Heap remains [0x02000000,0x0201C000). Dynamic save blocks/DMA margins, battle/decompression globals and original heap-backed temporary allocations remain inside their original reservations. `src/load_save.c` copies into the heap and moves save pointers only within the separately reserved save blocks. EWRAM literals were audited in the pinned source; no allocator reaches into the new section.

IWRAM globals still end at 0x03007480, user stack starts at 0x03007E40, IRQ stack at 0x03007FA0. The original 2496-byte globals-to-user-stack gap is unchanged. This is an allocation/margin audit, not a measured worst-case stack-depth proof. PING uses only a small bounded stack array and no heap allocations or IRQ work. No save buffer, flash layout or serialization hook was modified; the mailbox is transient and never serialized to battery save.

`gPiCompiledLayout` in the ROM contains the compiler's actual size and every offsetof. The builder reads it at its ELF-derived ROM address and compares the schema. C typedef assertions also enforce all offsets and size. The manifest contains ROM SHA-1/SHA-256/CRC32, compiled build tag/address, ELF/map hashes, schema, source/overlay hashes, worktree-dirty status, target flags, bridge script version/hash and exact mGBA pin. No timestamp enters ROM or identity. The disabled build's SHA-256 matches Phase 0 exactly.

## Mailbox ABI

Single authoritative schema: `bridge/protocol.json`; C declarations generated by `tools/generate_pi_protocol.py`. All integers unsigned, little-endian, aligned naturally, no pointers/bitfields. Protocol/schema version **1**, 32-byte payload cap. The complete offset/size table is in the generated manifest and `include/pi_protocol.h`.

| Bytes | Fields | Ownership |
|---|---|---|
| 0–11 | magic u32, version u16, size u16, build_tag u32 | ROM initializes; bridge reads only |
| 12–19 | nonce u32, generation u32 | bridge writes only at authenticated HELLO while IDLE |
| 20–23 | sequence u32 | ROM increments once per request |
| 24–35 | response_sequence, response_nonce, response_generation u32 | bridge publishes correlated response identity |
| 36–47 | state, message_type, length, result, error, reserved u16 | publication ownership below; reserved remains zero |
| 48–51 | checksum u32 | current publisher |
| 52–71 | heartbeat, deadline, last_ack, successes, failures u32 | ROM only |
| 72–75 | debug_trigger u32 | test harness sets 1; ROM clears/constructs request |
| 76–107 | payload[32] | ROM request publisher / bridge response publisher |

FNV-1a-32 checksum covers little-endian sequence, nonce, generation, type u16, length u16 and exactly length payload bytes. Responses use response identity fields. This detects accidental corruption; it is not authentication. Only exact PING `POKE` and PONG `PONG` (length 4, result/error 0) are accepted. The ROM checks length before reading/checksumming a response. Empty, oversized or unknown message bodies cannot affect gameplay.

## State machine and guarantees

- **IDLE (0):** no outstanding request. ROM accepts only debug_trigger=1 or the debug-only L+R+SELECT chord. It increments sequence, fills identity/body/checksum/deadline and publishes REQUEST_READY last.
- **REQUEST_READY (1):** ROM yields each main-loop iteration. The authenticated bridge validates bounds/content/checksum, records pending identity and publishes REQUEST_IN_PROGRESS.
- **REQUEST_IN_PROGRESS (2):** bridge queues at most one request. A matching, valid PONG writes body/response identity first and RESPONSE_READY last.
- **RESPONSE_READY (3):** ROM validates type/body/checksum and all three correlation fields, records last_ack/successes and returns IDLE. A response already published when ROM runs wins that iteration's deadline race.
- **ERROR (4):** ROM invalid response/timeout or bridge malformed/disconnect diagnostic. On the next ROM tick return to IDLE, retaining sticky error. Header/version corruption stays visibly in ERROR until reset. ROM heartbeat keeps advancing even in degraded mode. `failures` counts ROM-detected failures; bridge-published errors are logged separately.

One request at a time. No waiting loop, no new task/UI/story gate and no interrupt handler. Tick runs once near `ReadKeys()` in `AgbMain`, independent of game callbacks. Diagnostic deadline is 60 ROM ticks, approximately one normal-play second; it is not a tactical budget. No wall-clock wait is performed in Lua. Main-loop/save pauses and fast-forward affect wall-clock timing; fast-forward is not validated here.

Sequence starts 0 and first request is 1. At 0xFFFFFFFF, a new request is refused rather than wrapping/reusing identity. Host caches at most 64 exact requests per session: an identical duplicate returns identical PONG, conflicting duplicates and older uncached IDs are rejected. Lua accepts one response for its exact pending tuple; duplicate/stale/out-of-phase responses are logged and discarded. A timed-out request cannot be revived.

ROM reset clears RAM and initializes the header, IDLE, sequence=0, nonce/generation=0 and counters=0, publishing magic last. Active Lua reset callback/heartbeat regression closes the client and increments its connection generation. Reauthenticate explicitly after reset; no blocking reconnect in emulator frames. Fresh emulator launches must use `phase1_launch.py`, which generates a fresh random nonce and 128-bit token. Fresh script loading closes the preceding bridge. Arbitrary savestate/rewind or independently resetting only the scripting controller is not a supported identity/persistence workflow; those remain future save/transport gates.

Host absence leaves REQUEST_READY until the ROM's deadline; timeout error is visible in log/counters and ordinary input remains active. Host disconnect clears pending transport and reports DISCONNECTED; the ROM continues. mGBA restart discards transient connections/mailbox; battery save is unchanged. Unsupported manifest/protocol/build is refused before integration. Lua verifies whole-ROM CRC32 through the actual emulator API and an ELF-derived compiled tag; the Python launcher/host verify SHA-256 of the local ROM and the bridge script. CRC32/tag are compatibility checks, not resistance to malicious colliding ROMs. No cloud secrets enter mailbox/logs.

## Minimal transport

Lua listens only on 127.0.0.1:18770; Python connects. No Lua `connect()` call. mGBA's pinned source confirms listener/accepted sockets are nonblocking and socket callbacks poll with timeout 0. The generated trusted launch script embeds the generated manifest and private launch configuration, avoiding an untrusted JSON/eval decoder. Network bytes are decoded only as bounded binary messages.

Transport envelope: little-endian u16 body length (36–100), then `<4sHHIIIIHHHHI`: magic `PI01`, version, kind, nonce, generation, sequence, build_tag, type, payload_length, result, error, FNV checksum, followed by payload. Kinds: HELLO0, REQUEST1, RESPONSE2, HELLO_ACK3. HELLO payload is the private 32-character token followed by 32 raw ROM-SHA256 bytes (64 total); generation/sequence/type=0. Matching HELLO in IDLE establishes generation and gets HELLO_ACK; no request is forwarded before it. Game payload cap remains 32, and implemented PING is exactly four bytes.

Receive once per frame, at most 128 bytes; at most two decoded messages/frame, 256-byte RX/TX caps, one client and one pending game request. Short writes retain the unsent tail for later frames. Authentication/HELLO has a 120-emulator-frame deadline. Failures close the connection, clear buffers and log; retry is explicit host lifecycle work. Only the Python test process performs wall-clock connection retries and sleeps for fault injection. No executable content/arbitrary filesystem path crosses transport.

This small PING envelope/handshake is test scaffolding within BRIDGE-01. Production transport hardening, load/branch identity, broad adversarial framing/backpressure tests, crash recovery, durable delivery and gameplay events belong to BRIDGE-02 and later tickets.
