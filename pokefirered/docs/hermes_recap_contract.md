# Hermes recap envelope ownership — D50

The unchanged domain schema is [hermes_recap_v1.json](../schemas/hermes_recap_v1.json). Its `schemaVersion` const is infrastructure metadata. It is not a subjective content selection or a migration requested by Hermes. The original tool schema/prompt required the model to repeat it; the original adapter forwarded the result unchanged. That was a transport ownership defect, not a missing domain migration or a parser dropping a field.

D50, explicitly authorized by the ROCKET-01 disposition, moves envelope construction to the trusted host. [recap_contract.py](../puppeteer/recap_contract.py) reads the supported version from the canonical schema. The model-facing content schema is derived from that schema by removing host-owned `schemaVersion`, `actorID`, `battleID` and `obligationID`. [prompt v3](../prompts/hermes_recap_v3.txt) requests only evidence references, prior episode references, template, tone and public visibility. The trusted job supplies version and bound identities; runtime provenance/model/prompt hashes remain host generated.

The generic JobTools adapter accepts either content-only output or a compatible older complete envelope. Missing host fields are supplied; supplied fields must match in value and type. Unsupported old/future versions, bool/string/float/null versions and conflicting actor/battle/obligation IDs are rejected. Unknown content fields, malformed arrays, unauthorized/foreign evidence, missing mandatory outcome, unavailable prior memory and omission of supported participant-action evidence remain rejected by the same strict domain validator. The model cannot override metadata. This applies to every supported trainer through one path, without Rocket-specific conditions.

Domain serialization, schema/reducer version, disclosure limits and deterministic fallback are unchanged. Future domain schema migrations require explicit compatibility work; editing a prompt does not authorize migration or rewrite existing results. Historical prompt v1/v2, full responses, invalid proposals, fallback results and frozen post/episode hashes remain evidence. A terminal fallback or live result is never reopened merely because the adapter/model later recovers.

## Discard-only qualification

[QualificationStore](../puppeteer/qualification.py) requires an existing, explicitly owned **synthetic** database with a namespace/campaign/path binding and fixture build. It refuses the active campaign before opening its writer. It uses the production JobTools adapter, complete evidence retrieval, actual Hermes process, prompt, parser and strict `_validate_result`. Only its final sink differs: it updates isolated qualification job/audit diagnostics and archives the validated proposal. It never invokes publication, EPISODE, delivery or follower services, on success or failure. There is no `postID` and no active-campaign obligation.

The existing `shadow` production mode is **not** this facility: production shadow validation commits a fallback. It is therefore inappropriate for this non-committing acceptance disposition. A successful qualification returns `qualificationValid=true`, `committed=false` and a test namespace. Its output cannot satisfy an active campaign grant; source IDs, campaign/build and job identity are different, and terminal grants reject late submissions.

Actual worker interruption distinguishes `qualification_valid_discard_only` from `game_recap_committed`. The parent counts and bounds every hosted POST, including failed attempts. No successful test proposal enters public/social/director/faction memory. Test output is archived as qualification evidence only, then the owned runtime home is cleaned safely. Current normal hosted inference remains disabled.

ROCKET-01's amended acceptance pairs successful non-committing live qualification with the **unchanged historically committed fallback**. It does not relabel the real encounter as having produced a live Hermes recap. Exact repair, historical failure chain and accepted evidence are [the disposition report](rocket01_hermes_disposition.md).
